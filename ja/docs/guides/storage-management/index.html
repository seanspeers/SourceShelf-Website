SourceShelfのストレージを管理

SourceShelfは、削除するまでライブラリのソースを保持します。年齢ベースまたは500ソースの制限はありませんので、古い研究、スター付きのソース、保存パックのメンバーは静かに消えることはありません。

使う SourceShelf > 設定 > 一般 > ストレージのレビュー… SourceShelf が何を使用しているか確認し、削除する項目を選択します。

ストレージの概要を理解する #

概要インベントリは、SourceShelfが管理および生成したデータを要約します。これには、以下が含まれます。

  • 出力フォルダにマークダウンが生成されました。
  • 生成されたMarkdownの横に作成された画像フォルダ。
  • 管理されたライブラリコピーとアーカイブされた画像。
  • プレビュー、チャンキング、比較に使用されるセマンティックキャッシュ。
  • ローカルAIアクセススナップショット；
  • Safari のキャプチャのレビューのドラフトとステージングデータ。

概要では、元のインポートされたドキュメントをSourceShelfストレージとして扱っていません。変換したPDF、Wordドキュメント、スプレッドシートなどのソースファイルは、決してクリーニング対象ではありません。

選択する 思い出す 変換、キャプチャ、エクスポート、またはデータを削除した後、ウィンドウが開いている状態で合計を再計算したい場合は。

安全なクリーニングを実行する #

安全なクリーニング 孤立した、時代遅れ、期限切れ、またはもはや承認されていない内部データのみを削除します。

  • もはやライブラリソースに属していない管理されたコピー。
  • もはやMarkdownと一致しないセマンティックキャッシュ。
  • アクティブなキャプチャまたはレビューの一部ではない、期限切れのSafariのステージングデータ。
  • 取り消された MCP スナップショットと放棄された MCP ステージングデータ。

生成されたMarkdown、現在のライブラリエントリ、アクティブなレビュードラフト、公開されたものは削除されません。 MCP 株式、またはオリジナルのインポート文書。

SourceShelf は、クリーニング前のファイルと回収可能なスペースの推定数を表示します。 選択する 片付け...、確認を確認し、準備ができたらのみ続行してください。

生成されたソースデータを削除する #

その 生成されたソースデータ リストは意図的にソースごとに削除するためのものです。各行にはソースタイトル、推定サイズ、およびそれに適用された保護が表示されます。

  1. 個々のソースを選択するか、選択してください。 保護されていないを選択する。
  2. 選択数と推定サイズを確認します。
  3. 選択する 選択したものをゴミ箱に移動する...。
  4. 確認事項を読み、選択してください。 ゴミ箱に移す。

選択したソースごとに、SourceShelf：

  • 生成された Markdown と隣接する生成された画像フォルダを macOS のゴミ箱に移動します。
  • プライベート管理されたライブラリコピーを削除します。
  • 対応するライブラリエントリを削除します。

元のインポートされたファイルは決して選択または削除されません。生成された出力はゴミ箱に移動されても、ゴミ箱が空になるまで回復可能ですが、内部管理されたデータとライブラリレコードは削除されます。後でMarkdownファイルを復元する場合は、再度インポートして新しいライブラリエントリを作成してください。

保護されたソース #

星が付いたソースと保存されたパックで参照されているソースは、デフォルトでロックされています。それらの行は、なぜ保護されているのかを説明しています。

意図的に削除したい場合は、 スターマークまたは保存済みパッケージのソースを選択できるようにする、ソースを選択し、削除を確認します。保存されたパックソースを削除しても、パックは静かに書き換えられません。代わりに、使用できないプレースホルダーが残り、後でパックから復元したり削除したりできます。

保護は、ストレージウィンドウでの誤った選択を防ぐものです。バックアップではありません。重要なソース素材とエクスポートされたパックは、別のバックアップを保管してください。

ライブラリの削除とストレージのクリーニングの比較 #

これらのコマンドは異なる目的を果たします。

  • ライブラリから削除する ライブラリレコードを削除しますが、生成されたMarkdownは出力フォルダに残ります。
  • 安全なクリーニング 孤立したまたは再生可能な内部データのみを削除します。
  • 選択したものをゴミ箱に移動する... 選択したライブラリレコードとそのSourceShelfで生成された出力全体を削除します。

定期的なメンテナンスには、安全なクリーニングから始めます。生成されたソースの削除は、ソースシェルフに変換またはキャプチャされた結果を使用しなくなった場合にのみ使用します。

実用的なメンテナンスルーチン #

必要なスケジュールはありません。ストレージの使用量が目立つようになったら：

  1. 開いている ストレージを確認する... そして在庫を更新します。
  2. 安全なクリーニングを実行します。
  3. ライブラリでもう必要ないソースを整理します。
  4. 保護されていない生成されたソースデータを確認し、確認済みの項目のみをゴミ箱に移動します。
  5. 復元する必要がないことを確認したら、後で macOS のゴミ箱を空にします。

ストレージ境界の詳細については、 プライバシーとセキュリティ。
