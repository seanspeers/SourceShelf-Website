# ファイルとフォルダを変換

SourceShelfは、サポートされているローカルドキュメントをアップロードしたり、ネットワークリクエストを実行したりすることなく、Markdownに変換します。

## コンバージョンを開始する方法

- ファイルまたはフォルダを dragged して **改宗する**。
- 選択する **ファイルを選択する** いや **フォルダを選択する**。
- 使う **ファイル>開く** ファイルのために。
- 使う **ファイル>インポート llms.txt…** 地元の人にとって `llms.txt` インデックスまたはコレクションフォルダ。
- 自動化されたファイル変換には、SourceShelfショートカットアクションを使用します。

フォルダを変換するときは、SourceShelfはフォルダ内のサポートされているファイルをスキャンし、スキップされたアイテムを報告します。フォルダ変換では、フォルダ自体を保存済みパックに変換しません。その結果生じたライブラリアイテムは、後でパックに追加してください。

## 何が保存されていますか

SourceShelfは、新しいMarkdownをレンダリングする前に、意味のあるドキュメントを構築します。ソースに応じて、見出し、段落、リスト、表、コード、画像、キャプション、スライドまたはページ境界、および生のフォールバックコンテンツを保持できます。

スキャンされたPDFや画像の場合、SourceShelfはローカルOCRを使用します。インストールされているmacOSバージョンで構造化ドキュメント認識が利用可能な場合は、構造化ドキュメント認識を使用します。古いシステムでは、互換性OCRパスを使用します。

## 出力名と衝突

生成された名前は、ファイルシステム用にバリデーションされます。 目的先にすでに同じ名前が含まれている場合は、SourceShelfは、無音で上書きする代わりに、衝突防止の名前を選択します。

ソースファイルのパスは、ローカルでのOpenおよびRevealアクションのために保持されますが、エクスポートされたマニフェストには置かれません。 MCP スナップショット、またはファイル変換用の生成された原産地情報。

## 意味キャッシュ

管理対象のアイテムについては、SourceShelf ストアが `semantic-document.json` アイテムのプライベート管理ディレクトリにあります。キャッシュがまだ有効かどうかを判断するために使用される正確なMarkdownバイトチェックサムが含まれています。

別のアプリケーションでMarkdownを編集した場合、SourceShelfはチェックサムの変更を検出し、必要に応じて再解析します。編集したファイルを書き直すことはありません。欠落または損傷したセマンティックキャッシュはノンブロッキングです。

## 変換に失敗した場合

1. ソースがまだ存在し、通常のアプリケーションで開くことができることを確認します。
2. 出力フォルダが **設定>一般**。
3. フォルダ全体ではなく、単一のファイルを試して、フォーマットを分離します。
4. スキャンするには、ページが垂直で、OCRに十分なコントラストがあることを確認してください。
5. ファイルタイプが [サポートされているフォーマット](../reference/supported-formats.md)。
